# 한국어 학습 플랫폼 상세 기획서

개정판 v2.0 · 2026년 10월 14일 · 운영 정책 검토용

**한국어를 공부하고, 설명을 이해하고, 실제 수업까지 이어지는 학습 플랫폼.**

목적은 한국어 학습 기회를 넓히는 것이다. 교사에게 수업 준비와 학생 관리 도구를 제공하고, 학습자는 자신의 설명 언어로 자습한 뒤 교사와 수업한다. 무료 수업으로 연결과 지속 학습을 검증한 다음, 유료 수업과 크레딧을 단계적으로 도입한다.

이번 개정의 핵심은 기능 목록을 실제 운영 흐름으로 연결하는 것이다. 학생 가입, 기존 기록 연결, 교사 신청, 일정 확정, 참여, 수업 완료를 각각 구분하고 실패·취소·분쟁 상황까지 정의한다.

**문서 상태.** 서비스 구현을 완료했다는 보고서가 아니라, 기존 합의와 신규 권고를 함께 담은 상세 기획안이다. ‘기존 방향’은 원본과 저장소 결정 기록을 계승한다. ‘권고안’은 이번 검토에서 제시한 운영 기본안이며, ‘출시 전 결정’은 운영자가 확정해야 하는 항목이다. 법률·세무 관련 분류는 전문가 확인 전 확정하지 않는다.

**산출물.** 이 Markdown이 편집 원본이며, 같은 내용을 PDF로 제공한다. 2026-10-14의 원본 PDF 11쪽은 보존한다. 앱 소스, 실제 요금제, 배포 환경, 운영 정책 설정은 이 문서 개정만으로 변경되지 않는다.

## 01. 서비스 목적과 해결할 문제

### 핵심 가치

교사는 PDF와 직접 입력으로 단원을 만들고 학생의 학습을 관리한다. 학생은 모국어 또는 이해 가능한 설명 언어로 짧게 복습하고, 자신에게 맞는 교사와 실제 수업을 한다. 자습 내용과 수업 내용이 연결되는 것이 서비스의 중심이다.

기존 방향은 교사 우선 모집, 설명 언어별 학습방, 무료·유료 수업의 공존이다. 수익은 운영 지속성을 위한 수단이며, 무료 수업의 공급과 품질을 유지하는 것이 별도 목표다.

### 검증할 가설

- 학생 가설. 드문 설명 언어를 지원하고 자습과 수업을 연결하면 첫 수업 진입과 재학습이 늘어난다.
- 교사 가설. 자료 준비와 진도 관리 시간을 줄이면 교사가 기존 학생을 데려오고 신규 학생도 받는다.
- 무료 수업 가설. 참여 교사가 반복적으로 시간을 제공할 동기가 있고, 학생이 실제로 예약에 참석한다.
- 유료화 가설. 무료 운영에서 가치가 확인된 뒤 일부 학생이 유료 수업을 구매하며, 교사 보상과 운영비를 감당할 수 있다.

### 초기 대상과 언어

국내 외국인 학습자와 해외 한국어 학습자를 대상으로 하되, 첫 모집 집단은 운영자가 실제 교사와 학생을 확보할 수 있는 집단으로 좁힌다. 모든 국가·언어에서 동시에 모집해야 한다는 뜻은 아니다.

설명 언어의 기존 범위는 영어·중국어·일본어·태국어·스페인어·베트남어·네팔어·힌디어 8개다. 설명 언어와 국적을 동일시하지 않는다. 다국어 구조는 8개를 지원하되 운영 개시는 교사 공급과 번역 검수가 준비된 언어부터 한다.

### 범위 밖

초기에는 학위·자격 발급, 공인 봉사시간 인증, 자체 화상회의 시스템, 자동 교사 추천, 구독제, AI 교사 서비스를 만들지 않는다. 학습 활동 수를 늘리는 것보다 기존 활동의 정확성과 실제 수업 연결을 우선한다.

## 02. 현재 상태와 이번 개정의 변경점

### 현재 상태의 근거

원본 기획서와 저장소 checklist.md·context-notes.md에는 다음 기능이 구현된 것으로 기록되어 있다. 이번 작업에서 실제 운영 환경 전체를 다시 시험한 것은 아니다. 다음 구현 작업의 시작 시점에 코드·테스트·배포 상태를 별도로 확인한다.

| 영역 | 기록된 현재 기능 | 후속 확인 사항 |
|---|---|---|
| 교사 | 관리자 승인, 공개 프로필, 홈 소개 카드 | 공개 상태와 승인 회수 시 접근 차단 |
| 교재 | 단원 관리, 공용 단원, PDF 변환 | 번역·정답 품질과 사용 권한 |
| 학생 | 코드·6자리 PIN 접속, 학습 활동 9종 | 직접 가입 및 기존 기록 연결은 계획 |
| 학습 | 진도 현황, XP, 반 리더보드 | XP는 보상 근거로 신뢰하지 않음 |
| 기반 | HTML 번들, Firebase Auth·Firestore | 배포된 규칙과 저장소의 일치 |

학습 활동은 단어카드·4지선다·매칭·선잇기·받아쓰기·빈칸·문장 순서·OX·PDF 퀴즈다. 단원 난이도는 기초·중급·고급·마스터를 유지한다. 원본의 테스트 41개 통과는 당시 기록이며 이번 개정의 재실행 결과가 아니다.

### 기존안 대비 개정

| 기존 내용 | 상세 개정안 |
|---|---|
| 교사 수락 후 수업 시작 | 교사 연결, 일정 확정, 실제 참여, 완료를 분리 |
| 2단계 자습 후 3단계 수업 예약 | 2단계부터 무료 수업 일정·결과를 최소 기록 |
| 하루 한 번 기록으로 보상 | 습관 기록과 서버 검증된 보상 근거를 분리 |
| 무료 수업 개설 교사에게 크레딧 | 사용처 검증 전 지급 유예 권고 |
| 유료 개설 보증금 | 초기 도입 유예 권고, 추후 재결정 |
| 계정 통합을 나중에 결정 | 2단계 설계의 선행 조건으로 이동 |
| 교사 10명 확보 | 공개 수 외에 실제 수업 공급량 측정 |
| 3.3% 일괄 원천징수 | 교사별 적용 세무 기준 확인 후 반영 |

기존 루트 체크리스트는 과거 구현 이력으로 보존한다. 신규 작업의 우선순위와 수용 기준은 이 개정안에 따르되, 권고안을 운영 정책으로 채택한 날짜는 별도로 기록한다.

## 03. 단계별 범위와 전환 조건

### 1단계. 수업 가능한 교사 확보

기존 교사용 도구, 승인, 공개 프로필을 기반으로 모집한다. 소개 페이지에는 교사가 얻는 도구, 무료 수업 참여 방식, 비용 부담, 문의 경로를 명시한다. 프로필 수와 실제 활동 교사 수를 구분한다.

완료 조건은 승인 기준 확정, 모집 문구 준비, 설명 언어·수준·시간대별 공급 파악이다. 공개 교사 10명·설명 언어 4개라는 기존 목표는 모집 참고값으로 유지하되, 첫 파일럿을 여는 절대 조건으로 삼을지는 재결정한다.

### 2단계. 자습에서 첫 무료 수업 완료까지

학생 직접 가입, 핵심 화면 다국어화, 교사 연결 신청, 공용 단원 자습, 무료 수업 일정 확정, 결과 확인, 신고·차단을 포함한다. 크레딧 구매·지급·소급 적립은 포함하지 않는다.

일정은 외부 예약 도구를 이용할 수 있다. 다만 플랫폼에 수업 일시, 교사·학생, 확정 상태와 결과가 남아야 한다. 수락 버튼만으로 수업 완료로 집계하지 않는다. 운영자가 수동으로 보조하는 파일럿도 허용한다.

### 3단계. 거래와 보상 도입

3A에서는 서버 검증, 구매 크레딧, 유료 예약, 취소·환불, 정산을 먼저 검증한다. 3B에서는 학습 결과 검증과 무료 좌석 공급이 준비된 뒤 받은 크레딧을 도입한다. 두 종류의 원장은 처음부터 구분하되 보상 정책은 한 번에 모두 열지 않는다.

상용 호스팅 적합성, 법률·세무 검토, PG 계약, 비용 한도, 거래 복구 절차가 갖춰져야 실제 판매를 시작한다. 유료화를 시작했다는 이유만으로 보증금과 교사 보상 크레딧을 함께 도입하지 않는다.

### 4단계. 앱 안 커뮤니티

외부 커뮤니티에서 지속적인 교류와 언어별 관리자를 확보한 뒤 검토한다. 글·작문 공유를 먼저 열고 좋아요 보상은 별도 실험으로 다룬다. 월 수업 수가 늘었다는 사실만으로 커뮤니티 개발에 착수하지 않는다.

### 단계 전환 원칙

지표와 운영 준비를 함께 본다. 지표가 충족돼도 권한 누출, 미해결 정산 불일치, 안전 신고 처리 부재가 있으면 다음 단계를 열지 않는다. 목표에 못 미치면 신규 기능 확대보다 실패한 흐름을 먼저 개선한다.

## 04. 사용자와 수업 운영의 기본안

### 역할

| 역할 | 할 수 있는 일 | 제한 |
|---|---|---|
| 방문자 | 서비스 소개와 가입 안내 보기 | 학생·교사 연락처와 학습 기록 접근 불가 |
| 학습자 | 자습, 교사 신청, 본인 수업 참여 | 타인의 기록·예약·잔액 접근 불가 |
| 승인 교사 | 단원 제작, 신청 처리, 수업 진행 | 연결되지 않은 학생 기록 접근 불가 |
| 승인 대기 교사 | 본인 신청 상태 확인 | 교사 도구·학생 명단 접근 불가 |
| 운영자 | 승인, 신고 처리, 거래 조사 | 조회·정정 목적과 처리 이력을 남김 |

### 2단계 수업 형태 권고

첫 파일럿은 1:1 무료 수업으로 시작하는 안을 권고한다. 일정 합의와 출석 확인을 단순하게 검증할 수 있기 때문이다. 수업 길이는 30분을 후보로 제시하되 교사의 실제 제공 가능 시간과 사용하는 화상회의 계정 조건을 확인한 뒤 확정한다. 이는 기존 합의가 아니라 출시 전 결정 항목이다.

그룹 수업은 3단계 이후 확장 후보로 둔다. 도입 전 최소·최대 인원, 모집 마감, 인원 미달 취소, 학생별 출석·환불 규칙을 추가한다. 1:1 예약을 여러 학생에게 복제하는 방식으로 그룹 예약을 대신하지 않는다.

### 교사 관계 권고

학생 계정과 교사 관계는 별도로 관리한다. 초기 UI는 활성 담당 교사 1명을 기본으로 제한하는 안을 권고하되, 데이터는 교사 UID를 학생의 영구 소유자처럼 취급하지 않는다. 교사 변경 시 계정과 자습 기록을 유지한다. 여러 교사 동시 수강은 공개 전에 접근 범위를 검증한 뒤 연다.

### 비용과 책임 안내

2단계 학생 수업료는 무료다. 교사의 AI·화상회의 비용은 각자 부담하는 기존 방향을 안내하고, 외부 도구 결제나 개인 계좌 송금이 플랫폼의 무료 수업 조건인 것처럼 요구되지 않게 한다. 운영자가 판매자가 되는 3단계에는 수업 이행·고객 지원·환불 책임도 함께 설계한다.

## 05. 가입과 기존 학생 계정 연결

### 신규 학생 가입

학생은 역할 선택, Google 로그인, 연령 요건 확인, 설명 언어·시간대 선택, 필수 약관 확인을 거쳐 학습자 홈으로 들어간다. 로그인 성공만으로 교사 계정을 자동 생성하지 않는다. 탈퇴·가입 중단·인증 실패 시 다음 행동을 학생 언어로 안내한다.

만 14세 이상만 받는 기존 결정을 유지한다. 출생 연도만으로 만 나이를 판단하지 않는다. 생년월일 입력 후 요건 충족 여부를 판정하는 방식을 권고하되, 원본 생년월일의 수집·저장 필요성과 보존 범위는 개인정보 설계 때 확정한다. 단순 자기신고가 실제 신원 확인과 같다고 표시하지 않는다.

### 기존 코드·PIN 학생

기존 학생은 코드·PIN 방식으로 계속 학습할 수 있게 한다. 직접 가입 출시가 기존 로그인이나 진도를 초기화하는 이유가 되어서는 안 된다. Google 연결은 별도 안내를 통해 선택하게 한다.

권고 흐름은 기존 코드 계정으로 먼저 인증한 뒤 Google 계정을 연결해 같은 학습자 식별자를 유지하는 방식이다. 연결 전 이름·진도 요약을 본인에게 보여 주고, 성공 후 이전·새 로그인 정책을 안내한다. 교사가 발급한 코드만 알고 있다는 이유로 다른 계정의 기록을 자동 이전하지 않는다.

### 이미 두 계정이 있는 경우

Google 계정에 이미 별도 학습 기록이 있으면 자동 병합하지 않는다. 두 계정의 소유를 확인하고 충돌 항목을 보여 주는 별도 절차가 필요하다. 2단계 최소 범위에서는 자동 병합을 제외하고 운영 지원으로 접수한다. 안전한 서버 처리와 복구 수단이 준비되기 전에는 데이터 이동을 실행하지 않는다.

### 보존과 복구

- 학생 내부 ID는 표시 이름·이메일과 분리한다. 동명이인이나 이메일 변경으로 진도가 섞이지 않는다.
- 연결 시 기존 단원 진도와 교사 관계를 보존하고 중복 XP 합산은 하지 않는다.
- 학생이 전환을 취소하거나 연결이 실패하면 기존 계정으로 계속 사용할 수 있어야 한다.
- 교사의 PIN 재발급이 학생의 연결된 Google 계정까지 임의로 탈취하는 경로가 되지 않게 한다.
- 마이그레이션에는 이전 ID, 새 ID, 확인 주체, 처리 시각, 복구 상태를 남긴다. 비밀번호·PIN은 기록하지 않는다.

## 06. 교사 찾기와 연결 신청

### 목록과 프로필

가입자는 승인된 교사 중 공개 상태인 프로필을 본다. 설명 언어, 가르칠 수준, 가능 시간대, 현재 신규 신청 수락 여부를 표시한다. 표시 이름·소개·경력 요약만 공개하고 전화·이메일·주소·회의 링크는 공개 프로필에 넣지 않는다.

프로필의 ‘가능 시간’은 예약 가능한 확정 슬롯과 다르다는 점을 표시한다. 결과가 없으면 다른 시간대나 언어 조건을 제안하고 자습으로 돌아갈 수 있게 한다. 교사가 있다고 표시하면서 실제 신청을 모두 막는 빈 상태를 숨기지 않는다.

### 연결 신청 상태

| 상태 | 실행 주체와 의미 | 다음 처리 |
|---|---|---|
| 대기 | 학생이 설명 언어·수준·희망 시간 제출 | 교사 수락·거절, 학생 철회 |
| 수락 | 교사가 학습 관계를 승인 | 일정 협의로 이동 |
| 거절 | 교사가 수업 제공 곤란을 알림 | 다른 교사 탐색 가능 |
| 철회 | 학생이 대기 신청 취소 | 필요 시 새 신청 |
| 만료 | 응답 기한 경과 | 재신청 또는 다른 교사 탐색 |

응답 기한은 72시간을 권고 후보로 둔다. 기한·중복 신청 한도는 운영자가 출시 전에 확정한다. 같은 교사에게 대기 신청을 반복 생성하지 못하게 하고, 미응답은 성공한 연결로 집계하지 않는다.

### 관계 종료와 접근 회수

수락은 수업 예약 확정이 아니다. 수락 시 담당 관계만 생성하며 취소·차단·승인 회수로 관계가 끝나면 이후 연락처·수업 자료 접근도 정책에 맞춰 회수한다. 이미 열람한 연락처를 회수할 수 있다는 보장은 하지 않는다.

교사는 자신과의 수업 및 공유가 허용된 진도만 본다. 다른 교사의 메모·신고·연락처까지 공유하지 않는다. 다중 교사 수강을 도입할 때도 관계별 권한을 유지한다.

### 연락처 공개

2단계 외부 예약 링크는 유효한 연결 관계의 학생에게만 공개할 수 있다. Zoom 입장 링크는 확정된 수업의 당사자에게만 공개하는 것을 권고한다. 예약 안내 링크와 실제 회의 링크를 같은 공개 필드로 취급하지 않는다.

## 07. 일정 확정과 첫 무료 수업 완료

### 최소 예약 기록

외부에서 일정을 정하더라도 수업 ID, 교사·학생 ID, 시작·종료 시각, 표시 시간대, 수업 형태, 확정 상태, 취소 사유, 완료 확인이 플랫폼에 남아야 한다. 외부 도구의 예약 내역이 자동 동기화된다고 가정하지 않는다.

2단계는 교사가 외부 예약 또는 학생과 합의한 시간을 플랫폼에 제안하고 학생이 확인하는 방식을 권고한다. 같은 교사의 겹치는 수업과 학생의 중복 예약을 점검한다. 서버 없는 파일럿에서는 교사가 최종 일정을 확인하는 운영 절차를 병행하고 자동 정원 보장을 약속하지 않는다.

### 진행 순서

1. 연결 수락 후 학생이 희망 시간을 제시하거나 외부 예약 도구에서 선택한다.
2. 교사가 플랫폼에 일정과 수업 안내를 기록한다. 학생 현지 날짜·시간을 함께 표시한다.
3. 학생이 일정을 확인하면 ‘예약 확정’으로 바뀐다. 이때까지 회의 링크는 숨긴다.
4. 수업 전에는 다음 수업, 준비할 단원, 입장 방법, 취소 경로를 보여 준다.
5. 수업 종료 후 교사가 진행 여부를 기록하고 학생이 참석 여부를 확인한다.
6. 두 기록이 맞으면 완료로 집계한다. 불일치하거나 응답이 없으면 ‘확인 필요’로 남긴다.

### 시간대와 변경

시각은 UTC 기준으로 저장하고 사용자에게는 선택한 시간대의 날짜·시간을 보여 주는 설계를 권고한다. 시간대는 이름으로 관리해 서머타임 변화를 처리한다. 일정 변경은 기존 확정을 유지한 채 제안을 별도로 두고, 양측 확인 후 적용한다. 한쪽이 변경했다고 상대가 이미 동의한 것으로 보지 않는다.

### 참여와 알림

초기에는 다음 수업 목록과 앱 안 알림을 필수로 둔다. 이메일·메신저 알림은 발송 주체, 동의, 비용, 실패 대응이 정해진 경우에만 추가한다. 수업 시작 직전 링크 오류가 나면 교사·운영자 문의 경로를 제공한다. 입장 버튼 클릭은 출석 증거로 단독 사용하지 않는다.

### 무료 수업 취소 권고

학생은 취소할 수 있어야 하며, 무료 파일럿에는 크레딧 벌점을 적용하지 않는다. 반복 노쇼는 사유 확인 후 예약 제한을 검토한다. 제한 기준과 이의 신청 경로를 사전에 고지한다. 교사 취소는 대체 일정 제안 또는 종료로 처리하고 학생 노쇼로 기록하지 않는다.

## 08. 학습방·진도·학습한 날

### 자습 경험

학생은 교사 연결 전에도 공용 단원에서 공부한다. 언어별 학습방에는 이어서 공부하기, 수준별 단원, 학습한 날, 교사 찾기, 다음 수업을 배치한다. 빈 단원·번역 누락·저장 실패 상태에서 다시 시도하거나 다른 단원을 선택할 수 있어야 한다.

설명 언어가 같아도 수준은 다를 수 있으므로 언어와 수준을 별도 선택값으로 둔다. 공용 단원과 교사 단원의 출처를 구분하고, 공용 단원 수정 시 기존 진도 식별자가 불필요하게 바뀌지 않게 한다.

### 세 종류의 기록

| 기록 | 목적 | 신뢰 범위 |
|---|---|---|
| XP·게임 점수 | 학습 동기와 활동 표시 | 금전·수업권 지급 근거로 사용하지 않음 |
| 학습한 날 | 습관과 재방문 표시 | 2단계에는 보상과 연결하지 않음 |
| 검증된 학습 완료 | 3B 보상 자격 판단 | 서버가 결과·중복·기한을 확인 |

‘학습한 날’의 권고 후보는 서로 다른 채점 활동 2개를 각각 70% 이상 완료한 날이다. 초급자에게 불리한지 파일럿에서 검증한 뒤 조정한다. 단어카드의 자기평가 버튼만 반복한 것은 인정하지 않는 안을 권고한다. 숫자는 아직 확정 정책이 아니다.

### 날짜 기준

2단계 습관 표시는 학생의 선택 시간대를 사용하되, 시간대 변경으로 같은 활동이 여러 날짜에 중복 계산되지 않게 한다. 3B 보상일은 고정된 운영 기준 시간대(권고안은 Asia/Seoul)로 계산하고 화면에 기준을 명시한다. 개인 학습 달력과 보상일이 다를 수 있음을 설명한다.

### 보상 도입 조건

서버가 완료 세션 ID, 활동·문항 버전, 제출 답안, 점수, 완료 시각, 지급 여부를 확인해야 한다. 브라우저가 보낸 점수 하나만 신뢰하지 않는다. 서버 검증도 사람의 실제 이해나 다계정 사용을 완전히 증명하지는 못하므로 지급 한도와 이상 패턴 검토를 병행한다.

2단계 과거 기록에는 크레딧을 소급 지급하지 않는 안을 권고한다. 소급 보상을 원하면 별도 검증 기준과 최대 지급량을 먼저 승인한다. 리더보드는 표시 이름만 사용하고 공개 범위·참여 선택권을 제공한다.

## 09. 교재 품질과 AI 사용 정책

### 콘텐츠 작성 흐름

교사는 직접 입력하거나 PDF를 AI로 변환해 초안을 만든다. 어휘 뜻, 문법 설명, 정답, 난이도와 대상 언어를 검수한 뒤 학생에게 공개한다. AI가 만든 결과는 자동으로 공용 단원이 되지 않는다.

교사 개인 단원과 공용 단원은 발행 권한을 분리한다. 운영자는 공용 단원의 출처와 검수 상태를 확인한 뒤 발행한다. 오류 신고가 들어오면 잘못된 문제를 비공개 또는 수정하고 영향을 받은 점수·보상 처리 여부를 확인한다.

### 업로드와 외부 전송

업로드 화면에 사용 권한이 있는 교재만 사용하도록 안내한다. 학생 명단·연락처·상담 기록 등 수업 자료와 무관한 개인정보를 넣지 않도록 한다. PDF 또는 추출 내용이 어느 AI 제공자에게 전송되는지 변환 전에 알린다. 제공자별 보관·학습 이용 조건은 실제 계약과 설정을 확인한다.

원본 보관 여부, 보관 기간, 삭제 방법을 정한다. 교재를 변환할 수 있다는 사실이 저작권이나 재배포 권한까지 확인해 주는 것은 아니다. 공개·배포 권한이 불분명한 자료는 공용 단원으로 발행하지 않는 운영 기준을 권고한다.

### 교사 개인 AI 키

현재 개인 키 사용 방향은 유지하되, 평문 브라우저 저장을 안전한 보관으로 표현하지 않는다. 키 저장 여부 선택, 키 삭제, 공용 PC 주의, 노출 시 제공자에서 폐기하는 방법을 안내한다. 키를 로그·학생 화면·공개 문서에 포함하지 않는다.

서버 대행으로 옮기는 경우 운영자 비용과 남용 방지를 먼저 설계한다. 교사별 사용량 한도, 비용 알림, 요청 제한, 실패·중복 요청 처리, 제공자 장애 대응이 필요하다. 서버 도입만으로 콘텐츠 권리와 개인정보 문제가 해결된다고 보지 않는다.

### 품질 기준

필수 설명 언어가 빠진 단원은 해당 언어에서 미지원임을 표시한다. 다른 언어가 섞인 문장과 잘못된 정답은 발행 전에 수정한다. 학생은 문제별 오류를 신고할 수 있으며 교사는 신고된 단원과 영향을 바로 확인할 수 있어야 한다.

## 10. 화면과 다국어·접근성 요구사항

### 핵심 화면

| 화면 | 꼭 보여 줄 정보 | 실패·빈 상태 |
|---|---|---|
| 랜딩 | 대상, 무료 학습, 교사 참여 방식 | 운영 중 언어와 모집 상태 |
| 가입 | 역할, 연령, 언어, 약관 | 인증 실패·미충족 안내 |
| 학생 홈 | 이어 학습, 다음 수업, 신청 상태 | 첫 활동·교사 찾기 안내 |
| 교사 찾기 | 언어·수준·가능 시간·모집 상태 | 조건 변경·자습 경로 |
| 신청함 | 대기·응답·만료·철회 | 중복 신청·저장 실패 |
| 내 수업 | 현지 시각, 확정 여부, 입장·취소 | 링크 오류·확인 필요 |
| 교사 관리 | 학생 관계, 일정, 결과 확인 | 승인 회수·불러오기 실패 |
| 지갑·정산 | 사용 가능·예약 중 잔액, 거래 내역 | 환불 처리 중·정산 보류 |

### 다국어 범위 권고

메뉴와 버튼뿐 아니라 가입·신청·예약·취소·오류·신고·결제 확인 문구까지 학생의 설명 언어로 제공한다. 정책의 법적 원문과 번역본의 관계를 명시하고 중요한 동의 내용은 이해 가능한 형태로 안내한다. 번역이 없으면 임의로 한국어만 노출하지 말고 대체 언어와 미지원 상태를 표시한다.

교사의 자유 소개문은 지원 언어를 표시한다. 자동 번역을 제공한다면 원문과 구분하고 완전한 정확성을 보장하지 않는다. 언어 선택은 국기만으로 표현하지 않는다.

### 화면 원칙

학생은 휴대폰에서 한 화면의 주 행동을 쉽게 찾도록 한다. 교사는 PC에서 신청·일정·진도를 빠르게 확인하도록 한다. 저장 실패는 사라지는 알림에만 맡기지 않고 상태와 재시도 버튼을 남긴다. 긴 번역문·큰 글자·좁은 화면에서도 중요 버튼이 잘리지 않아야 한다.

기존 인디고·앰버·성공·위험 색상은 유지하되 정답·오류를 색만으로 구분하지 않는다. 키보드 이동, 입력 이름, 읽기 순서, 충분한 대비를 검수한다. 서비스 이름과 로고는 랜딩 공개 전에 정하되 계정·예약 정책 결정보다 앞선 개발 차단 조건으로 삼지 않는다.

## 11. 교사 운영과 학습자 안전

### 승인과 품질

교사 모집 대상은 한국어교원, 자격 준비생, 봉사자라는 기존 방향을 유지한다. 모든 승인 교사가 자격증 보유자인 것처럼 표시하지 않는다. 확인된 자격·경력과 자기소개를 구분한다.

권고 승인 기준은 연락 가능한 본인 확인, 설명 언어 확인, 수업 가능 시간 확인, 간단한 시범 수업 또는 자료 검토, 운영 수칙 동의다. 제출 자료의 접근 주체와 삭제 시점을 정하고 공개 프로필에는 검증 결과만 필요한 범위로 표시한다.

### 미성년자와 직접 연락

만 14세 이상 정책이어도 14~17세 이용자가 존재한다. 연령 제한만으로 미성년자 보호가 완료됐다고 보지 않는다. 불필요한 개인 연락 요구, 부적절한 메시지, 외부 송금 요구, 수업 외 만남 요구에 대한 신고 경로와 처리 담당자를 둔다.

수업 녹화는 기본 기능으로 제공하지 않는 안을 권고한다. 필요 시 목적, 당사자 안내·동의, 보관, 열람, 삭제 정책을 별도로 정한다. 원본 영상 없이도 신고를 접수할 수 있어야 한다.

### 신고·차단 절차

1. 사용자가 교사·학생·수업·콘텐츠를 특정해 신고한다. 불필요한 민감정보 제출은 요구하지 않는다.
2. 운영자가 접수 상태를 알리고 위험도를 분류한다. 긴급 사안의 우선 대응 경로를 정한다.
3. 필요하면 신규 연결·예약을 임시 제한한다. 신고가 곧 사실 확정이라는 뜻은 아니다.
4. 관련 당사자의 설명과 필요한 기록을 검토하고 조치·사유·이의 신청 방법을 안내한다.
5. 접근 권한을 회수하고 보존이 필요한 기록과 삭제할 정보를 구분한다.

신고는 당사자 외 일반 사용자에게 공개하지 않는다. 단순 차단과 진행 중 수업의 취소·환불은 별개로 처리한다. 담당자 부재 시 대체 담당 또는 접수 중단 안내가 있어야 한다.

### 봉사 참여 안내

교사에게 확인 가능한 수업 횟수·시간 기록과 감사 확인서를 제공하는 방안을 검토한다. 공식 봉사시간, 교원 실습, 자격 취득 실적으로 인정된다고 약속하지 않는다. 인정기관과 절차가 확인된 경우에만 별도 안내한다.

## 12. 학습방과 커뮤니티 운영

### 단계 구분

학습방은 공용 단원을 공부하는 제품 공간이며, 커뮤니티는 사람 사이의 대화 공간이다. 학생은 외부 채팅방에 가입하지 않아도 자습하고 교사를 신청할 수 있어야 한다. 핵심 수업 알림을 외부 채팅방에만 올리지 않는다.

2단계는 언어별 외부 채팅방 링크로 시작하는 기존 방향을 유지한다. 다만 운영 가능한 관리자와 신고 경로가 없는 언어의 방은 열지 않는다. 외부 서비스의 가입 연령·개인정보·초대 링크 정책을 실제 도입 시 확인한다.

### 외부 커뮤니티 개설 조건

- 방의 목적, 사용 언어, 금지 행동, 운영 시간과 신고 방법을 고정 안내한다.
- 전화번호나 실명이 다른 참여자에게 노출되는지 확인하고 가입 전 알린다.
- 초대 링크의 유출·도배 발생 시 회수·교체할 담당자를 둔다.
- 수업 자료·학생 기록·회의 입장 링크를 전체 방에 올리지 않는다.
- 외부 서비스에서 발생한 신고를 플랫폼이 어디까지 처리할지 명확히 한다.

### 앱 안으로 옮길 조건

주간 활동이 지속되고 해당 언어를 읽을 수 있는 운영 담당자가 있으며, 신고 처리량을 감당할 수 있을 때 검토한다. 글 수만으로 옮기지 않는다. 외부 대화를 사용자의 동의나 적절한 근거 없이 일괄 복사하지 않는다.

초기 앱 커뮤니티는 질문·작문·피드백에 집중한다. 글 수정·삭제, 신고·차단, 운영자 조치 이력을 포함한다. 좋아요 수를 곧바로 크레딧으로 바꾸지 않는다. 상호 좋아요·다계정 조작과 운영 비용을 별도 검증한 뒤 보상 여부를 결정한다.

## 13. 크레딧 정책과 무료 좌석 공급

### 기본 원칙

산 크레딧과 받은 크레딧은 별도 잔액과 원장으로 관리한다. 학생 간 양도·선물·현금 교환은 초기 범위에서 제외한다. 교사 강사료는 완료된 유료 수업의 정산으로만 발생하며, 받은 크레딧에서 현금 지급이 생기지 않는다.

| 종류 | 생성 근거 | 사용처 | 반환·환불 |
|---|---|---|---|
| 산 크레딧 | PG 결제 서버 확인 | 유료 수업 예약 | 취소 시 크레딧 복원, 결제 환불은 별도 |
| 받은 크레딧 | 검증된 보상 정책 | 지정 무료 수업 예약 | 조건에 따라 복원, 현금 환불 없음 |
| 교사 강사료 | 유료 수업 완료·확정 | 교사 지급 | 분쟁·환불 시 정산 조정 |

크레딧 단가·구매 묶음·수업 가격·유효기간은 출시 전 결정이다. 결정 전에는 가격이나 만료일을 사용자에게 약속하지 않는다. 유료 구매와 보상 지급의 규칙 버전을 거래에 함께 기록한다.

### 보상 크레딧 도입 순서

2단계에는 크레딧 없이 무료 수업을 제공한다. 3B에서 검증된 학습 완료를 보상으로 전환한다. 학생 화면에는 잔액만이 아니라 예약 가능한 무료 수업과 다음 공급 예정도 보여 준다. 크레딧이 있다고 항상 원하는 수업을 받을 수 있는 것처럼 표현하지 않는다.

운영자는 언어별 무료 좌석 수, 예약 대기, 미사용 보상 잔액을 주기적으로 확인한다. 공급이 부족하면 모집과 일정 확대를 우선하고 향후 지급량 조정을 검토한다. 이미 적립된 권리를 예고 없이 삭제하는 방식으로 해결하지 않는다.

### 교사 보상과 보증금

무료 수업 교사에게 받은 크레딧을 주는 기존안은 사용처가 확인될 때까지 유예하는 것을 권고한다. 교사 연수·상호 수업 같은 사용처는 실제 공급이 생겼을 때 별도 기획한다. 단순 수업 개설은 보상 조건이 될 수 없다.

유료 수업 개설 보증금도 초기에는 유예를 권고한다. 반복 취소·노쇼 기록과 개설 제한으로 관리 가능한지 먼저 본다. 추후 도입하려면 보증금 출처, 동결액, 반환 시점, 몰수 사유, 이의 제기, 폐업·탈퇴 시 처리를 모두 정해야 한다.

## 14. 예약·크레딧 사용의 상태와 예외

### 유료 예약의 권고 흐름

서버는 수업의 판매 가능 상태와 가격 버전, 학생 자격, 중복 예약, 잔액, 정원을 함께 검사한다. 성공하면 예약을 확정하고 필요한 크레딧을 예약 중 금액으로 묶는다. 잔액만 차감되거나 자리만 확보된 불완전 상태를 정상 완료로 표시하지 않는다.

수업 전까지는 ‘사용 가능’과 ‘예약 중’을 구분한다. 완료 확정 또는 정책에 따른 노쇼 처리가 끝난 뒤 최종 사용으로 전환한다. 1:1 수업은 정원 1명이며 그룹 수업을 도입하면 마지막 좌석 동시 예약을 서버가 원자적으로 처리해야 한다.

| 사건 | 예약 상태 | 금액 처리 | 강사료 |
|---|---|---|---|
| 정상 예약 | 확정 | 사용 가능에서 예약 중으로 이동 | 아직 발생하지 않음 |
| 정상 수업 완료 | 완료 확인 후 확정 | 예약 중에서 사용으로 전환 | 정산 후보 생성 |
| 교사 취소·노쇼 | 교사 귀책 취소 | 전액 크레딧 복원 | 원칙적으로 발생하지 않음 |
| 학생 조기 취소 | 학생 취소 | 정책에 따른 복원 | 사전 고지된 기준 적용 |
| 학생 지연 취소·노쇼 | 결과 확인 필요 후 확정 | 정책에 따른 일부·전부 사용 | 동일 기준으로 정산 |
| 서비스·회의 장애 | 확인 필요 | 최종 사용·정산 보류 | 원인 확인 후 결정 |
| 그룹 인원 미달 | 개설 취소 | 전액 복원 권고 | 발생하지 않음 |

무료 크레딧 예약에도 동일한 예약 상태를 사용하되 교사 강사료는 생성하지 않는다. 무료 파일럿의 출석 기록을 유료 거래 확정 권한으로 재사용하지 않는다.

### 동시성과 중복

예약·취소·결제 알림은 고유 처리 ID를 가지며 재시도해도 한 번만 반영한다. 브라우저 새로고침, 네트워크 끊김, PG 알림 재전송, 같은 버튼 연속 클릭을 정상적으로 발생할 수 있는 상황으로 취급한다. 예약 확정 후 가격이 바뀌어도 기존 예약 금액은 바뀌지 않는다.

### 일정 변경

예약 확정 이후 교사가 시간을 바꾸면 학생 재동의를 받는다. 동의하지 않으면 교사 변경에 따른 취소로 처리한다. 학생 요청 변경은 기존 예약의 취소와 새 예약의 관계를 기록해 크레딧이 이중 복원·차감되지 않게 한다.

## 15. 취소·환불·노쇼·분쟁 정책

### 출시 전에 확정할 정책

2단계 무료 수업은 자유 취소와 사유 확인을 기본으로 한다. 3단계 유료 수업은 수업 시작 전 취소 구간, 지각 허용 범위, 노쇼 판정, 환불 기준을 법률 검토와 함께 확정한다. 임의의 수치를 이 문서에서 확정 약관처럼 제시하지 않는다.

학생은 예약 전에 적용 규칙을 확인하고 예약 당시 정책 버전을 보존한다. 정책 변경이 기존 예약에 자동 소급되지 않게 한다. ‘취소하기’와 ‘결제 환불 요청’을 다른 기능으로 안내한다.

### 크레딧 복원과 결제 환불

수업 취소에 따른 크레딧 복원은 내부 잔액 처리다. 현금·카드 결제 환불은 원결제와 PG 확인이 필요한 별도 절차다. 미사용 산 크레딧은 환불 요청을 받을 수 있도록 하고, 청약철회·부분 사용·할인 구매·수수료 적용은 검토된 규칙으로 처리한다.

구매별 충전 묶음과 사용 내역을 연결해 남은 환불 가능 금액을 계산한다. 환불할 잔액은 처리 중 동결하고 PG 성공 확인 뒤 확정한다. PG 응답을 잃은 경우 상태 조회로 결과를 확인한다. 실패·결과 불명 상태에서 환불 완료로 표시하거나 동일 금액을 반복 환불하지 않는다.

### 출석과 노쇼 확인

교사는 수업 후 진행·학생 미참석·기술 문제를 기록한다. 학생은 참석·교사 미참석·문제 발생을 확인할 수 있다. 한쪽 신고만으로 불리한 금액 처리를 즉시 확정하지 않는다. 응답 기한과 운영자 판정 기준은 정책으로 정한다.

수업 입장 클릭이나 회의 접속 로그는 보조 근거다. 수업 품질과 실제 진행 시간을 자동 증명한다고 보지 않는다. 분쟁 중인 예약은 정산 보류로 분리하고 관련 없는 수업까지 일괄 보류할지는 별도 기준에 따른다.

### 정산 후 환불

이미 강사료를 지급한 수업도 환불·결제 취소가 생길 수 있다. 계약에 근거한 차기 정산 조정이나 별도 회수 절차를 정의한다. 원장을 삭제하거나 과거 지급액을 조용히 덮어쓰지 않고 조정 거래로 남긴다. 교사의 이의 제기와 운영자 판정 이력을 보존한다.

## 16. 강사료 정산과 운영 책임

### 판매자 구조

운영자가 수업 판매자이고 교사는 프리랜서 강사라는 기존 사업 방향을 유지한다. 이 명칭만으로 법률상 관계가 확정되는 것은 아니다. 실제 가격 결정, 수업 계약, 환불 책임, 강사 업무 방식과 일치하는지 검토한다.

유료 수업 수입의 50%를 강사료로 월 1회 지급하는 기존 방향을 유지하되, ‘수입’의 계산 기준은 확정해야 한다. 결제 총액인지, 부가세·할인·PG 수수료·환불 반영 후 금액인지 계약과 화면에 동일하게 적는다.

### 계산 예시의 범위

아래는 ‘완료 수업 금액에서 교사 50%, PG 비용은 운영자 부담’이라는 가정의 설명용 예시다. 실제 수업료·세금·요율을 결정한 것이 아니다.

- 학생이 사용한 유료 수업 금액을 10,000원으로 가정한다.
- 정산 기준액이 10,000원이라면 교사 세전 강사료는 5,000원이다.
- 운영자에게 남는 5,000원에서 해당되는 결제 비용·세금·서버·지원 비용 등이 추가로 나간다.
- 교사 실지급액은 교사별 적용 원천징수 등 확인 후 계산한다. 모든 교사에게 3.3%를 일괄 적용하지 않는다.

### 정산 절차

1. 월 마감 시 완료 확정된 유료 수업을 모으고 취소·환불·분쟁 건을 구분한다.
2. 수업별 기준액, 교사 비율, 세전 강사료, 세금, 조정액을 계산한다.
3. 운영자가 PG·크레딧 사용·정산 합계를 대조하고 불일치를 조사한다.
4. 교사가 명세를 확인하고 정해진 기한 내 이의를 제기할 수 있게 한다.
5. 지급 후 실제 지급 확인 정보와 시각을 기록한다. 지급 실패는 미지급 상태로 남긴다.

### 지급과 정보 보호

계좌·세무 정보는 공개 프로필·수업 문서와 분리한다. 정산 담당자만 필요한 범위에서 접근한다. 거주자 여부, 용역 제공 장소, 사업자 여부, 조세조약 등 적용 사항을 확인한다. 해외 교사에게 지급할 수 있는 수단과 비용이 준비되지 않았다면 유료 교사 등록 범위를 명확히 제한해 안내한다. [4]

### 현재 데이터와의 연결

기존 students·studentIndex·curricula·sharedCurriculum은 바로 삭제하지 않는다. 학생 ID 대응과 교사 관계를 정의한 뒤 단계적으로 이전한다. 구형 화면과 신형 화면이 동시에 쓰는 기간에는 어떤 쪽이 원본인지 명시해 진도 덮어쓰기를 방지한다.

교사에게는 본인과의 수업·과제 진도를 제공하고 학생의 전체 결제 내역과 다른 교사의 기록은 보여 주지 않는다. 학생의 관계 종료가 기록 전체 삭제를 뜻하는지, 보존된 완료 수업 요약만 남기는지는 보존 정책으로 정한다.

### 권한 검증

목록 조회까지 실제 규칙 조건으로 검증한다. 가입자라는 이유만으로 모든 예약·지갑·신고를 읽을 수 없어야 한다. 승인 회수·차단·관계 종료·예약 취소 시 접근이 즉시 달라지는 경우를 시험한다. 서버용 권한도 최소화하고 관리자 임의 금액 수정은 정정 사유와 원장 거래를 통해서만 수행한다.

## 18. 기술 구성·배포·운영 복구

### 2단계 최소 구성

기존 정적 웹과 Firebase Auth·Firestore를 활용한다. 단순 신청·당사자 확인은 보안 규칙으로 상태 전이를 제한하는 방식을 검토한다. 계정 간 병합, 자동 만료·알림, 거래 확정처럼 신뢰 가능한 서버가 필요한 작업은 서버 없이 되는 것처럼 약속하지 않는다.

초기 무료 파일럿은 운영자 수동 확인으로 일부 절차를 보완할 수 있다. 단, 개인정보를 일반 문서나 외부 채팅방으로 복사하는 방식으로 보완하지 않는다. 자동화가 없어서 처리 대기 중이면 상태와 예상 안내를 표시한다.

### 3단계 신뢰 경계

Cloud Functions 등 신뢰 가능한 서버에서 결제 확인, 잔액·원장, 예약 동시성, 환불, 정산을 처리한다. PG 결제 완료 화면을 본 것만으로 충전하지 않는다. 서버가 주문 소유자·금액·통화·결제 상태를 확인한 뒤 한 번만 기록한다. 서버 도입 방식과 실제 요금제는 구현 착수 시 공식 조건을 확인한다.

서버는 검증된 상태만 변경하고 클라이언트의 금액·교사 몫·완료 플래그를 그대로 믿지 않는다. 비밀 키는 클라이언트에 배포하지 않는다. 정산 파일·로그에도 결제 비밀과 인증 정보를 남기지 않는다.

### 호스팅과 배포

GitHub Pages는 상업적 거래를 촉진하는 것이 주목적인 서비스나 상용 SaaS용 무료 호스팅으로 허용되지 않는다. 유료 수업 중개가 시작되는 시점부터 적합성을 판단하고 판매 전에 이전을 완료한다. 결제 화면만 외부로 빼면 조건을 충족한다고 가정하지 않는다. [1]

코드 배포와 Firestore 규칙 게시를 별도 항목으로 검증한다. 저장소 수정·테스트 통과만으로 운영 규칙이 반영됐다고 보고하지 않는다. 시험 결제와 운영 결제, 시험 데이터와 실제 학생 정보를 분리한다.

### 장애와 복구

- 학습 저장 실패는 재시도 상태를 남기고 미저장 점수를 서버 저장 완료로 표시하지 않는다.
- 예약 중 통신 오류는 서버의 최종 상태를 조회한 후 재시도한다.
- PG 장애 때 신규 충전을 제한하되 기존 잔액과 예약 상태를 조회할 수 있게 한다.
- 원장과 PG 또는 정산 합계가 맞지 않으면 관련 거래 지급을 보류하고 조사한다.
- 백업·복원 방법, 담당자, 실제 복원 점검을 운영 개시 전에 준비한다. 무료 플랜에서 모든 백업 기능이 제공된다고 가정하지 않는다.

3단계는 월 수업 40회·노쇼 10% 이하라는 기존 목표를 무료·유료로 나눠 본다. 완료 수업 회차와 학생 참여 건수를 혼동하지 않는다. 그룹 수업 1회에 학생 5명이 참여하면 수업은 1회, 참여는 5건이다. 4단계는 언어별 주간 글 수와 함께 고유 작성자·답변·신고 처리 역량을 본다.

## 20. 법률·개인정보와 판매 전 관문

### 2단계 가입 공개 전

이용약관, 개인정보처리방침, 연령 확인, 탈퇴·삭제 요청, 신고 처리, 교재 권리 정책을 준비한다. 한국어·영어본을 우선 작성하되 실제 모집 언어의 사용자가 핵심 내용을 이해할 수 있도록 안내를 보완한다. ‘돈을 받지 않으니 약관과 개인정보만 필요하다’고 단정하지 않는다.

Firebase 및 외부 AI·화상회의·채팅 서비스의 실제 저장·처리 위치와 이전 관계를 확인한다. 필요한 고지·동의·계약·보존 기간은 실제 데이터 흐름을 기준으로 검토한다. 생년월일·국적·주소처럼 필요성이 불명확한 필드를 가입 편의를 이유로 추가하지 않는다.

금융위원회 2024년 안내의 발행잔액 30억 원 미만·연간 총발행액 500억 원 미만 기준은 등록 면제 검토의 참고 근거다. 먼저 이 서비스가 해당 수단인지 판단하고, 다음으로 등록 면제와 적용 의무를 구분한다. 운영자가 판매자라는 문구만으로 법 적용을 배제하지 않는다. 출시 시점의 현행 법령을 다시 확인한다. [3]

비거주자 교사는 국내원천소득 여부와 조세조약 등에 따라 처리가 달라질 수 있다. 3.3%를 전 세계 모든 교사에게 적용하는 확정 정책으로 두지 않는다. [4]

### 판매 개시 조건

위 표의 필수 판단이 끝나고 거래·환불·정산 시험이 통과하기 전에는 실제 충전금을 받지 않는다. 미확정 사항은 담당자·기한·판매 차단 여부를 결정 목록에 남긴다. 이 문서 자체는 법률·세무 검토 완료 증거가 아니다.

## 21. 비용과 지속 가능성

### 비용을 나누어 계산한다

1·2단계는 무료 도구의 한도 안에서 현금 지출을 줄일 수 있지만 운영비가 항상 0원이라는 보장은 없다. 번역 검수, 교사 모집, 신고 처리, 수업 확인에 드는 운영자 시간도 기록한다. Zoom·AI 비용을 교사가 부담한다면 교사 모집 안내와 비용 추정에 함께 적는다.

| 항목 | 1·2단계 | 3단계 이후 |
|---|---|---|
| 호스팅·도메인 | 정책에 맞는 호스팅과 필요한 도메인 | 상용 운영 조건·이전·트래픽 비용 |
| 인증·데이터 | Spark 제품별 한도 관찰 | 실제 사용량·지역별 과금 |
| 서버 | 수동 보조 범위와 자동화 구분 | 실행·저장·로그·배포 관련 비용 |
| AI·화상회의 | 교사 계정 조건 확인 | 대행·API 도입 시 별도 산정 |
| 결제·환불 | 없음 | 계약 수수료·세금·해외 결제·환불 비용 |
| 운영·안전 | 모집·검수·문의·신고 시간 | 정산·분쟁·세무·고객지원 시간 |

Firestore 무료 읽기·쓰기 할당량은 일 단위이고 태평양 시간 자정 무렵 초기화된다. 저장량·전송량 등은 다른 단위가 적용되므로 ‘한도 초과 시 모두 그달 말까지 중단’으로 적지 않는다. 제품별 한도와 회복 시점을 확인한다. [2]

### 단위 경제성

수업당 운영 기여액은 확정 수업 매출에서 강사료, 해당 결제 비용, 관련 세금, 변동 인프라 비용, 평균 환불·지원 비용을 뺀 값으로 관리한다. 충전된 현금 전체를 즉시 운영 이익으로 보지 않는다. 미사용 구매 잔액과 환불 예정액, 미지급 강사료를 별도로 추적한다.

무료 수업도 교사 시간과 운영 지원 시간을 사용한다. 유료 수익으로 어느 범위까지 무료 운영을 지원할지 결정하고, 무료 좌석 공급이 불안정하면 보상 발행을 무제한 늘리지 않는다.

### 가격표의 사용 방식

원본의 PG 3.4%, 가입·연관리비 및 서비스 무료 호출 수는 확정 예산에서 제외한다. 실제 업종·계약·지역·세금·해외 카드 조건에 따라 확인한 견적을 붙인다. 무료 호출 수가 있다고 서버 전체 비용이 무료라는 뜻은 아니다.

매월 현금 비용, 운영 시간, 오류·지원 건수, 무료·유료 수업별 기여를 점검한다. 지출 알림과 운영 중단·제한 절차를 준비하되 알림만으로 과금이 자동 차단된다고 가정하지 않는다.

## 22. 구현 순서와 출시 수용 기준

### 작업 순서

A. 수업 형태·교사 관계·계정 연결·연령 확인 방식을 확정한다. 학생 직접 가입과 기존 데이터 공존 설계를 먼저 검토한다.

B. 학생 가입, 핵심 다국어, 자습 홈, 교사 찾기와 신청을 구현한다. 로그인 실패·승인 대기·검색 결과 없음·신청 만료까지 함께 검수한다.

C. 무료 일정 제안·확정, 수업별 입장 정보, 완료 확인, 신고를 구현한다. 운영자 보조 절차와 처리 담당자를 정한 뒤 소규모 파일럿을 연다.

D. 첫 수업 완료·재학습·교사 공급을 관찰한다. 검증되지 않은 흐름은 고친 뒤 확대한다. 이후 서버·PG·원장·정산을 별도 작업으로 착수한다.

### 2단계 필수 검수

- 신규 학생이 교사 계정으로 자동 분류되지 않고 자습을 시작한다.
- 기존 코드 학생이 같은 계정 연결 후 진도를 유지한다. 충돌 계정은 자동 병합되지 않는다.
- 학생 A가 학생 B의 진도·연락처·예약을 읽거나 수정할 수 없다.
- 교사 연결 수락만으로 특정 수업 예약이나 출석 완료가 되지 않는다.
- 일정 제안·변경·취소가 양측 화면에서 일관되게 표시된다.
- 다른 시간대에서 날짜가 넘어가는 수업을 정확히 보여 준다.
- 링크는 확정 예약 당사자만 읽고 취소·차단 시 적용 정책대로 접근이 회수된다.
- 교사·학생의 완료 보고가 다르면 확인 필요로 남는다.
- 학생 언어로 가입·신청·오류·취소·신고를 끝낼 수 있다.
- 학습 기록 저장 실패와 인터넷 재연결 시 상태가 잘못 확정되지 않는다.

### 3단계 추가 검수

같은 PG 알림 2회에도 충전은 1회다. 동시 예약이 잔액 음수나 정원 초과를 만들지 않는다. 취소·환불 재시도가 잔액을 이중 복원하지 않는다. PG 처리 결과 불명 시 조회로 복구한다. 분쟁 수업은 정산되지 않는다. 환불·조정 후에도 원장·잔액·PG·강사료가 일치한다.

브라우저가 점수·잔액·교사 비율·가격을 바꿔 보내도 서버 값이 임의로 바뀌지 않아야 한다. 테스트 계정과 운영 계정을 섞지 않는다. 코드 테스트, 빌드, 실제 규칙 게시 확인, 파일럿 사용자 흐름 검증을 모두 통과해야 출시 완료로 기록한다.
