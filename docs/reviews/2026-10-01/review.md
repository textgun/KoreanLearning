# 프로젝트 2차 검토 결과

검토일. 2026-10-01.

검토 기준. `c870fb6`의 전체 소스와 저장소 내 Firestore 규칙. 애플리케이션 코드는 변경하지 않았다.

## 요약

`f9ea601` 이후 바뀐 것은 1차 검토 문서뿐이므로 [1차 검토](../2026-09-15/review.md)의 14건(P1 6건, P2 8건)은 모두 그대로 남아 있다. 이번 검토에서는 1차에 없던 문제 10건과 작은 개선점 11건을 새로 확인했다.

가장 시급한 것은 두 가지다. 첫째, 교사 자격이 서버에서 검증되지 않는다. 누구나 가입해 교사가 되고, 관리자가 삭제해도 다시 로그인하면 복구된다. 이 때문에 1차 #1(연결 문서 위조로 다른 반 접근)을 외부인도 쓸 수 있다. 둘째, 교사 기기의 학생 모드가 로그인 시점에 읽어 둔 학습 기록으로 서버 기록을 덮어써 원격 학습 결과가 사라진다.

등급 기준은 1차와 같다. P1은 접근 권한 침해나 데이터 유실, P2는 정상 사용 중 잘못된 동작이나 표시, P3는 작은 결함과 유지보수 개선이다.

## 새로 확인한 문제

### N1. [P1] 교사 자격을 서버가 검증하지 않아 삭제·제한이 무력하다.

- 위치. [firestore.rules](../../../firestore.rules) 56–63행, [firebase.js](../../../src/firebase.js) 150–156행·247–258행, [views-teacher.js](../../../src/views-teacher.js) 1884–1892행.
- 문제 1. 회원가입이 열려 있고, 규칙은 본인 UID로 `isAdmin == false`인 교사 문서 생성을 항상 허용한다. 인터넷의 누구나 즉시 교사 권한을 얻는다.
- 문제 2. 관리자 삭제는 `teachers`·`students` 문서만 지운다. 인증 계정과 `curricula/{uid}`가 남고, 다시 로그인하면 `onAuthLogin`이 교사 문서를 자동 생성한다. 삭제한 교사가 기존 단원까지 그대로 돌려받는다.
- 문제 3. '교육중' 제한은 화면 버튼만 숨긴다. 규칙은 교사 본인이 `status`와 관리자 메모 `note`를 고치는 것을 허용하고, 교육중 교사의 단원·학생 쓰기도 막지 않는다.
- 영향. 관리자가 교사를 내보낼 수 없다. 1차 #1과 결합하면 외부인이 가입만으로 다른 반 명단과 학습 기록에 접근할 수 있다.
- 조치. 교사 문서에 관리자만 바꿀 수 있는 승인 필드를 두고 `isTeacher()`가 이를 확인하게 한다. 교사 본인이 `status`·`note`·승인 필드를 수정하지 못하게 한다. 삭제는 Cloud Functions(Admin SDK)로 인증 계정 비활성화와 연결 데이터 정리를 함께 처리한다.
- 검증. 실제 `onAuthLogin`에 교사 문서가 없는 상태를 주입해 문서 재생성과 기존 단원 복원을 확인했다(`repro.js` [4]). 규칙의 허용 범위는 코드로 확인했고 에뮬레이터 실행은 하지 않았다.

### N2. [P1] 교사 기기 학생 모드가 오래된 캐시로 원격 학습 기록을 덮어쓴다.

- 위치. [storage.js](../../../src/storage.js) 235–237행(캐시 사용), 90행(통째 저장).
- 재현. 교사가 아침에 로그인해 명단을 읽는다. 학생이 집에서 원격 접속으로 학습해 XP 160, 퀴즈 최고점 90이 된다. 수업 중 교사 기기에서 같은 학생으로 학습 모드에 들어가 XP 10을 얻는다.
- 실제 결과. 서버 XP가 160에서 110으로, 퀴즈 최고점이 90에서 45로 내려갔다.
- 원인. 학습 모드 진입 시 서버를 다시 읽지 않고 로그인 때 받은 `studentDoc.stats`를 쓴다. 저장은 `stats` 전체를 보내므로 숫자 필드는 오래된 값으로 덮이고 배지 배열은 통째로 교체된다.
- 조치. 학습 모드 진입 시 학생 문서를 다시 읽는다. 저장은 변경분만 보낸다. XP는 `FieldValue.increment`, 배지는 `arrayUnion`, 최고점은 트랜잭션으로 큰 값만 남긴다. 1차 #5·#6의 저장 대기·대상 고정과 함께 고치는 것이 효율적이다.
- 검증. 실제 `loadStudentStats`와 `_doSaveStudent`를 중첩 맵 병합을 흉내 낸 대역 저장소로 실행했다(`repro.js` [2]).

### N3. [P2] 관리자가 보는 다른 교사 학생의 진도가 관리자 본인 단원 기준으로 계산된다.

- 위치. [views-teacher.js](../../../src/views-teacher.js) 1451행, 1127–1134행.
- 문제. `calcOverallProgress`는 `allUnits()`, 즉 로그인한 사람의 단원과 공용 단원만 순회한다. 관리자 상세 화면은 해당 교사의 `curricula`를 읽지 않는다.
- 결과. 담당 교사 화면에서 100%인 학생이 관리자 화면에서는 0%로 표시되었다. 공용 단원 진도만 반영된다.
- 조치. 상세 화면 진입 시 `curricula/{teacherId}`를 읽고, 진도 함수가 단원 목록을 인자로 받게 한다.
- 검증. 실제 진도 함수로 재현했다(`repro.js` [1]).

### N4. [P2] PDF 변환 응답이 잘려도 감지하지 못한다.

- 위치. [api.js](../../../src/api.js) 21·31행, [views-teacher.js](../../../src/views-teacher.js) 715행.
- 문제. Anthropic·OpenAI·Groq 경로의 출력 상한이 1,200토큰이고 `stop_reason`·`finish_reason`을 확인하지 않는다. 입력 텍스트도 6,000자에서 안내 없이 자른다.
- 영향. 어휘 10개짜리 샘플 단원을 지시 형식으로 출력해도 약 1,750자다. 어휘가 많은 교재나 태국어·힌디어처럼 토큰을 많이 쓰는 언어에서는 상한을 넘을 가능성이 높다. 잘린 JSON은 'AI 응답이 유효한 JSON이 아닙니다'로만 표시되어 원인을 알 수 없다. 6,000자 이후 내용은 조용히 빠진다.
- 조치. 상한을 4,096 이상으로 올리고 잘림 응답을 별도 오류로 안내한다. 입력을 자를 때는 몇 쪽까지 반영했는지 표시한다.
- 검증 수준. 상한 값과 확인 코드 부재는 코드로 확인했다. 실제 AI 호출로 잘림을 재현하지는 않았으므로 발생 빈도는 추정이다.

### N5. [P2] 단원 편집 내용이 자동 저장되지 않고 이탈 경고도 없다.

- 위치. [views-teacher.js](../../../src/views-teacher.js) 780행, 815–822행, 848–865행, 895–911행.
- 문제. 제목·단어·설명·예문·퀴즈 입력은 메모리만 바꾼다. 저장은 '← 단원 목록', '저장하기', 항목 추가·삭제 같은 구조 변경 때만 일어난다. `beforeunload` 처리가 없고, 상단 홈 버튼(`goHome`)과 로그아웃도 교사 저장을 하지 않는다.
- 영향. 편집 중 탭을 닫거나 새로고침·로그아웃하면 입력이 사라진다. 저장 상태 표시가 없어 교사는 저장된 줄 안다.
- 조치. 입력마다 지연 저장(`persistTeacher()`)을 예약하고, 저장 대기 중이면 이탈 경고를 띄운다.

### N6. [P2] OX 퀴즈가 올바른 문장을 '틀림'으로 채점한다.

- 위치. [views-student.js](../../../src/views-student.js) 413–426행, 문장 순서는 926행.
- 문제. X 문항을 예문 어순을 섞어 만든다. 한국어는 서술어 앞 성분의 순서가 자유로워 섞은 문장도 문법적인 경우가 많다. 샘플 단원에서는 '책을 도서관에서 읽었어요.'가 X 정답으로 출제된다. 문장 순서 게임도 원문 어순 하나만 정답으로 인정한다.
- 영향. 학습자에게 틀린 문법 지식을 가르친다. 샘플 단원 기준 X 문항의 약 4–5%이며, 성분이 많은 긴 예문일수록 비율이 커진다.
- 조치. X 문항은 조사·시제 교체처럼 실제로 틀린 변형으로 만든다. 문장 순서는 교사가 허용 어순을 추가할 수 있게 하거나 어순이 고정된 예문만 출제한다.
- 검증. 실제 출제 함수를 3,000회 실행해 확인했다(`repro.js` [3]).

### N7. [P2] 신규 교사에게 기본 제공되는 샘플 단원의 번역 14건이 손상되어 있다.

- 위치. [config.js](../../../src/config.js) 28–65행.
- 문제. 외국어 번역 칸에 한글이나 다른 문자가 섞여 있다. 퀴즈 힌트 중국어는 6건 모두 깨졌다. 4건은 한국어 문장 그대로이고, 2건은 '我在' 뒤에 한국어가 붙었으며 그중 하나는 '지구관'으로 단어도 틀렸다. 그 밖에 일본어 '공원', 네팔어 칸의 벵골 문자와 한글, 힌디어 'सि네마' 등이 있다.
- 영향. 모든 신규 교사의 첫 단원으로 저장되어 해당 언어 학생 화면에 그대로 표시된다. 이미 가입한 교사의 `curricula`에도 복사되어 있다.
- 조치. 데이터를 바로잡고, 한국어가 아닌 언어 칸에 한글이 들어가면 실패하는 검사를 추가한다. 기존 교사 문서의 샘플 단원은 별도 정정이 필요하다.
- 검증. 샘플 데이터 전수 검사로 확인했다(`repro.js` [5]).

### N8. [P2] 아이콘 라이브러리를 버전 고정 없이 외부에서 불러온다.

- 위치. [index.html](../../../src/index.html) 24행.
- 문제. `unpkg.com/lucide@latest`를 무결성 검사(SRI) 없이 불러온다. 이 페이지는 Firebase 로그인 세션과 localStorage의 AI API 키를 다룬다.
- 영향. 새 버전의 아이콘 이름 변경은 배포 없이 화면을 깨뜨린다. CDN이나 패키지가 오염되면 모든 사용자의 세션과 키가 노출된다.
- 조치. 버전을 고정하고 `integrity` 속성을 붙이거나 빌드에 포함한다. PDF.js도 같은 방식으로 SRI를 붙인다.

### N9. [P2] 공용 단원 발행도 목록 전체를 덮어써 다른 발행을 지운다.

- 위치. [views-teacher.js](../../../src/views-teacher.js) 561–590행.
- 문제. 발행·발행 취소가 로그인 시점의 `state.sharedUnits`에 한 건을 더하거나 빼서 배열 전체를 저장한다. 1차 #4와 같은 구조가 공용 문서에도 있다.
- 영향. 관리자가 두 기기에서 쓰거나 관리자가 여럿이면, 나중에 저장한 쪽이 그사이 발행된 단원을 지운다.
- 조치. 공용 단원을 단원별 문서로 나누거나 트랜잭션으로 읽고 쓴다.

### N10. [P2] 학생 데이터에 서버 검증이 없고 반 친구 정보가 필요 이상 노출된다.

- 위치. [firestore.rules](../../../firestore.rules) 82–116행(students 규칙), [views-student.js](../../../src/views-student.js) 496행·453–461행.
- 문제 1. 규칙은 학생이 `stats` 필드만 고치는지만 본다. 값의 형식과 범위는 검사하지 않아 XP를 임의 값으로 써서 리더보드 1위가 될 수 있다.
- 문제 2. 단어카드 '알아요'는 확인 없이 XP를 준다. 게임 종료 창은 '진행 상황은 저장되지 않습니다'라고 안내하지만 그때까지 얻은 XP는 저장된다. 반복 시작·종료로 XP를 쉽게 쌓을 수 있다.
- 문제 3. 리더보드용 목록 조회로 같은 반 학생 문서 전체가 내려간다. 화면에는 이름·국적만 보이지만 나이와 인증 UID까지 읽힌다.
- 조치. 규칙에서 `stats`의 형식·증가 폭을 검사한다. 리더보드는 이름·점수만 담은 별도 컬렉션으로 분리한다. 자가 보고형 활동의 XP는 낮추거나 하루 상한을 둔다.

## 작은 개선점 (P3)

1. 매칭·선잇기·받아쓰기의 점수 알림이 실제 가산점보다 크다. 콤보를 올린 뒤 알림 값을 계산하기 때문이다. [views-student.js](../../../src/views-student.js) 600·603행, 728·732행, 841·843행.
2. 리더보드가 연속 정답 수를 '일'로 표시한다. 이 값은 게임마다 0으로 초기화되는 콤보이지 연속 학습일이 아니다. [views-student.js](../../../src/views-student.js) 191행.
3. 교사 기기 학생 모드에서 학생이 고른 언어가 교사의 단원 언어 설정으로 저장된다. 이 설정은 PDF 변환 대상 언어도 바꾼다. [router.js](../../../src/router.js) 266행. 또 게임이 끝날 때마다 `persistAll(true)`가 교사 단원까지 저장해 1차 #4의 덮어쓰기 기회를 늘린다. [views-student.js](../../../src/views-student.js) 1034행.
4. '모든 단어 자동 번역' 버튼은 일본어가 빠진 단어도 세지만 실제 번역은 중국어가 빠진 단어만 대상으로 한다. 버튼이 남아 있는데 눌러도 '번역할 단어가 없습니다'가 나온다. [views-teacher.js](../../../src/views-teacher.js) 803행, 1019행.
5. 학생 코드와 PIN을 `Math.random`으로 만든다. PIN 경우의 수는 26만여 개다. `crypto.getRandomValues`로 바꾼다. [firebase.js](../../../src/firebase.js) 60·66행.
6. API 키 안내의 '외부로 전송되지 않습니다'는 사실과 다르다. 키는 선택한 AI 서버로 전송되고, Gemini는 URL 쿼리에 실려 기록에 남기 쉽다. `x-goog-api-key` 헤더를 쓴다. [router.js](../../../src/router.js) 197행, [api.js](../../../src/api.js) 38·77·92·110행.
7. 교사 단원 전체를 문서 하나(`curricula/{teacherId}`, `sharedCurriculum/main`)에 담는다. 샘플 단원이 약 8.1 KB라 문서 상한 1 MiB에 약 129개가 들어가며, 실제 교재 단원은 더 크다. 학생 로그인마다 전체를 읽는 비용도 같이 커진다.
8. '데이터 초기화'는 점수·레벨·배지도 지운다고 안내하지만 학생의 Firestore 기록은 그대로 둔다. [views-teacher.js](../../../src/views-teacher.js) 518–536행.
9. 쓰이지 않는 코드가 있다. `speak()`·`esc()`(utils.js), `autoTranslateVocab()`(views-teacher.js). `extract.py`는 다시 실행하면 `src/app.js`·`style.css`·`index.html`을 덮어쓰는 일회성 스크립트다.
