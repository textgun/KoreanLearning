## 우선 수정할 문제

### 1. [P1] 학생 연결 문서를 위조하면 다른 반에 접근할 수 있다.

- 위치. [firestore.rules](/home/piction/.openclaw/workspace/KoreanLearning-main/firestore.rules:130), 130–134행.
- 조건. 일반 교사가 대상 교사 UID 또는 학생 문서 ID를 알고 있다.
- 문제. 연결 문서 생성은 `teacherId`가 요청자와 같은지만 검사하고 `studentId`의 실제 소유권은 확인하지 않는다. 수정은 기존 `teacherId`만 검사하므로 새 `teacherId`를 다른 교사로 바꿀 수 있다. 자기 인증 UID에 이 연결 문서를 만들면 이후 규칙이 이를 학생 신원으로 신뢰한다.
- 영향. 다른 반 단원과 학생 명단 조회, 지정 학생의 학습 기록 수정이 가능하다.
- 조치. 연결 대상 학생의 실제 소유 교사 및 인증 UID를 검증하고, 수정 시 연결의 소유권을 변경하지 못하게 해야 한다.
- 근거. 규칙의 생성·수정 조건과 73·86·97·109–111행의 연결 참조를 교차 확인했다. `resource`와 `request.resource`의 의미는 [Firebase 공식 문서](https://firebase.google.com/docs/firestore/security/rules-conditions#data_validation)로 확인했다. 에뮬레이터나 운영 규칙에 대한 실행 검증은 하지 않았다.

### 2. [P1] 학생을 삭제해도 원격 접근 권한이 남는다.

- 영향. 삭제 전에 로그인한 학생은 기존 인증으로 해당 반의 단원과 다른 학생 명단을 계속 조회할 수 있다.

- 검증. 실제 삭제 함수를 메모리 DB 대역으로 실행하여 연결 문서가 남는 것을 확인했다. 후속 접근 허용은 저장소 규칙에서 확인했다.

### 3. [P1] 짝맞추기 카드에서 교재 내용이 HTML로 실행될 수 있다.

- 위치. [views-student.js](/home/piction/.openclaw/workspace/KoreanLearning-main/src/views-student.js:584), 584행.
- 조건. 직접 입력이나 PDF/AI 변환에서 HTML 이벤트 속성이 포함된 어휘·뜻·이모지가 저장된 단원을 연다.
- 문제. 데이터가 `innerHTML`에 그대로 삽입된다. 같은 화면의 다른 요소와 달리 텍스트 노드 생성이나 이스케이프를 거치지 않는다.
- 영향. 저장된 교재에 포함된 스크립트가 학습자 브라우저의 앱 권한으로 실행될 수 있다. 교사 세션에서 학습 모드를 사용하면 교사 권한과 기기에 저장된 API 키도 영향을 받는다.
- 조치. 카드 구조는 DOM으로 만들고 외부 입력은 `textContent`로 넣어야 한다.
- 검증 수준. 입력부터 표시까지의 코드 경로를 교차 확인했다. 무해한 표식만 설정하는 로컬 브라우저 재현을 시도했으나, 브라우저가 환경의 소켓 제한으로 시작되지 않아 실제 브라우저 실행 여부는 검증하지 못했다.

### 4. [P1] 서로 다른 단원을 편집해도 다른 기기의 변경이 사라진다.

- 위치. [storage.js](/home/piction/.openclaw/workspace/KoreanLearning-main/src/storage.js:52), 52–56행.
- 재현. A와 B가 단원 1·2를 로드한다. A가 단원 1을 수정하고 저장한다. 이어서 B가 단원 2만 수정하고 저장한다.
- 실제 결과. 단원 1은 수정 전 값으로 돌아가고 B의 단원 2 변경만 남는다. A가 삭제한 단원을 B가 되살리는 경우도 재현했다.
- 원인. 서버에서 새로 추가된 ID만 가져오고, 기존 ID는 수정 여부와 무관하게 로컬 사본 전체로 덮어쓴다. 기존 기록에 적힌 '같은 단원의 동시 편집'보다 영향 범위가 넓다.
- 조치. 로컬에서 실제 변경한 단원과 삭제한 단원을 추적하고, 읽기와 쓰기의 경합도 트랜잭션 또는 단원별 저장으로 처리해야 한다.
- 검증. 실제 저장 모듈을 두 개의 독립 실행 환경에 로드하여 순차 저장과 삭제 부활을 재현했다.

### 5. [P1] 저장 중 들어온 마지막 변경은 서버에 반영되지 않는다.

- 문제. `_savingTeacher` 또는 `_savingStudent`가 참이면 새 저장을 즉시 버리며, 진행 중 저장이 끝난 뒤 다시 실행하지 않는다. 즉시 저장 호출도 완료를 기다리지 않고 반환된다.
- 실제 결과. 교사 화면의 '마지막 변경' 대신 '첫 변경'만 서버에 남았다. 학생 점수는 서버에 XP 10, 화면과 캐시에는 XP 30으로 달라졌다. 학생 캐시도 실제 저장 성공 값과 다르게 갱신된다.
- 조치. 진행 중 저장을 기다리되 변경이 추가되면 마지막 상태를 반드시 다시 저장하고, 완료 안내는 실제 반영 결과에 연결해야 한다.
- 검증. 저장 응답을 지연시키는 메모리 대역으로 실제 함수를 실행하여 후속 요청이 사라지는 것을 확인했다.

### 6. [P1] 학생 전환 후 저장 재시도가 이전 학생에게 새 학생 점수를 기록한다.

- 검증. 실제 재시도 로직에 첫 요청 실패와 학생 전환을 넣어 재현했다.

## 검증 결과와 한계

- 소스 JavaScript 9개 모두 `node --check` 통과.
- 프로젝트를 임시 폴더로 복사해 `python3 build.py` 실행 성공. 결과 크기는 약 240.4 KB.
- 빌드 HTML의 인라인 스크립트 2개 문법 검사 통과. 앱 모듈 9개의 병합 순서와 루트·dist 사본 일치 확인.
- 저장 로직의 다섯 재현, 학생 게임의 세 재현, 공용 샘플 표시 및 진도 계산 재현을 실행했다. 모두 보고한 잘못된 결과를 확인하는 검사이며, 제품 동작이 정상이라는 의미의 통과가 아니다.
- 교사 변환·번역 및 인증·삭제 흐름도 실제 소스 함수에 메모리 대역을 연결해 검증했다. 실서비스 로그인이나 데이터 생성·삭제는 수행하지 않았다.
- 저장소에는 반복 실행할 수 있는 정식 테스트 묶음이나 패키지 테스트 명령이 없다. 과거 체크리스트에 적힌 테스트 통과 기록만으로 현재 회귀 검증을 재현할 수 없다.
- Firestore 규칙의 실제 게시 상태, 운영 데이터, AI 제공자별 실호출 결과와 브라우저 전체 화면 동작은 확인하지 않았다. 규칙 관련 문제는 저장소의 규칙이 적용된다는 전제다.
- 브라우저 재현은 시작 단계에서 `setsockopt: Operation not permitted`로 종료되었다. 이것은 실행 환경 제한이며 애플리케이션 오류로 집계하지 않았다.

## 권장 수정 순서

1. 반 접근 규칙과 학생 삭제 시 권한 회수, 교재 HTML 삽입을 수정한다.
2. 저장 요청의 순서·대상·재시도를 고정하고 실제 변경 단원만 병합한다.
3. 게임 종료와 중복 제출을 정리하고 점수·진도 재현을 회귀 검사로 남긴다.
4. 공용 단원 식별과 번역 갱신을 수정한다.
