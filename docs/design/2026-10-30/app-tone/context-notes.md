# 컨텍스트 노트

- 사용자 요청. "처음 만들었던 메인과 퀴즈의 디자인을 교사랜딩페이지와 톤엔매너를 일치시켜서 다시 만들어줘". 범위 질문에 "앱 전체 톤 + 메인·퀴즈 새 디자인", "학습 활동 전부"로 답했다.
- 기존 앱은 Plus Jakarta Sans, 인디고(#4f46e5)·슬레이트 색, 보라 그라데이션 배경, 반투명 흰 카드다. 스타일 파일은 하나(`src/style.css`)이고, 화면 코드에도 hex가 직접 박혀 있다(교사 158곳, 학생 34곳, 공통 11곳).
- 랜딩 톤. 크림 종이색 바탕(#faf6ee), 브라운 글자(#39251f), 노란 알약 버튼에 브라운 글자, 초록 포인트(#3f8065), DM Sans + Noto Sans KR, 굵은 제목과 좁은 자간, 영문 대문자 라벨(초록 점), 노란 사선 밑줄.
- 색 결정. `--primary`는 초록, 주 버튼은 노랑 바탕 + 브라운 글자, 선택 상태는 연노랑, 정답은 연초록, 오답은 연적색. 노랑은 글자로 쓰지 않고(대비 부족) 바탕·별·막대에만 쓴다. 글자용 겨자색은 #7a5a12, 아이콘용 금색은 #b8880f(3:1 이상)이다.
- 단계 색(config.js LEVELS)은 화면 코드가 `${color}33`으로 투명도를 붙이므로 var()가 아닌 hex로 둔다. 기초 #326852, 중급 #47739e, 고급 #ad5029, 마스터 #6a58a8. 모두 크림 바탕에서 4.5:1 이상이다.
- 선잇기 SVG 선은 속성값이라 var()를 쓰지 않고 hex로 둔다.
- 앱 이름. 상단 로고를 랜딩과 같은 "ㅁ 말이음" 표기로 바꾸고 "학습 도구"를 작게 붙인다. 화면 문구와 테스트가 확인하는 문구는 바꾸지 않는다.
- 루트 사본(`korean_learning_app.html`)은 이전 작업들처럼 갱신하지 않고, 빌드는 임시 폴더에서 확인한다. 배포는 CI가 `build.py`로 만든다.

## 구현 결정

- 커밋을 세 단계로 나눴다. 84f5b06 색·글꼴 교체(배치 그대로), 5ef50bc 메인 개편, 6d3e625 학습 화면 개편.
- 로그인 계열 화면은 공통 함수 renderAuthLayout으로 왼쪽 안내 문구와 오른쪽 입력 카드를 만든다. 로그인·가입·학생 접속 처리 로직은 그대로 옮겼다. 교사/학생 탭은 브라운 바탕의 알약형 전환 버튼이다.
- 홈 모드 카드는 랜딩 기능 카드처럼 색 아이콘·번호·영문 부제·태그·검은 원 화살표로 구성했다. 학생 선택은 이름 첫 글자 노란 원 카드다.
- 학생 단원 목록은 제목을 "OO님, 오늘은 어떤 단원을 배울까요?"로 바꾸고 단계 배지, 단계색 번호 원을 쓴다. 리더보드는 인라인 스타일을 클래스(leader-row 등)로 옮겼고, 모바일에서는 두 줄로 접힌다.
- 4지선다·빈칸·PDF 보기의 A~D 배지는 CSS counter와 ::before로만 그린다. 정답 판정이 버튼 textContent를 비교하므로 글자를 넣으면 판정이 깨진다.
- 주 버튼이 노랑으로 바뀌어 그 안의 흰 아이콘이 안 보이므로 `.btn-primary [data-lucide]`에 글자색을 강제했다. 흰 글자가 남은 곳은 초록·적색·단계색 바탕 위라 대비가 충분하다.
- 결과 아이콘은 별 3개 금색, 2개 하늘색, 1개 초록으로 구분했다.

## 검증

- npm test 48/48, 클라이언트 테스트 12/12 통과. 임시 폴더 빌드 성공, 빌드된 단일 파일 앱이 콘솔 오류 없이 로그인 화면을 그린다.
- Playwright로 1440·820·375px에서 로그인·홈·교사 관리·학생 단원 목록·단원·4지선다·단어카드·결과 화면을 캡처했다. 모든 화면에서 가로 넘침 0. 앱 브라우저 창에서 활동 9종을 모두 열어 확인했다.
- 미리보기는 로그인 없이 상태만 넣어 띄웠다. 앱 브라우저 창에서 결과 화면을 띄울 때 학습 기록 저장 시도가 있었지만 운영 Firestore 규칙이 모두 거부했다(Missing or insufficient permissions). 이후 캡처는 Firebase 요청을 차단하고 진행했다.
